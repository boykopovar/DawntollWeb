# Dawntoll

Дожить до первого света. Будущая браузерная 3D-игра о поезде, временной базе, заражённых и отправлении на рассвете.

0.1.1 — статический прототип: один хост, один гость, ручное соединение и чат. Игровой логики пока нет.

## Разработка

Node.js 22. Установка зависимостей не требуется.

```sh
npm run dev
npm test
npm run build
```

Откройте http://127.0.0.1:4173. Публикуется только dist/. Пути относительные, поддерживается подпапка GitHub Pages. Нужен современный браузер с WebRTC, CompressionStream и HTTPS (локально localhost).

## Подключение

1. Хост создаёт приглашение и передаёт гостю ссылку или QR.
2. Гость открывает или вставляет приглашение, создаёт ответ и возвращает ссылку хосту.
3. Хост вставляет ответ в исходную вкладку. После открытия канала доступен чат.

Обе вкладки должны оставаться открытыми. После перезагрузки нужен новый обмен. Ответ из QR нужно скопировать в исходную вкладку хоста: новая вкладка не восстанавливает его сессию.

Полные SDP с ICE-кандидатами обмениваются вручную вместо signaling-сервера. DataChannel использует DTLS/SCTP поверх ICE, сокетами управляет браузер. Публичные STUN Google и Cloudflare определяют внешний адрес, но не передают чат. TURN отсутствует: строгий NAT, VPN, мобильные сети и блокировка UDP могут препятствовать соединению. Гарантировать связь между любыми сетями без ретранслятора невозможно. Хост завершает неудачную попытку через 45 секунд после принятия ответа. Гость не ограничен таймером приложения во время ручного обмена.

Ссылки содержат сетевые адреса и параметры рукопожатия: передавайте их только попутчику. История хранится в памяти вкладки, ограничена 200 сообщениями. Текст отображается через textContent. Подтверждения прочтения нет.

## Архитектура

- web/src/network — WebRTC-транспорт и сжатый кодек signaling, без DOM.
- web/src/session — жизненный цикл, роли, идентификатор сессии и версионированный протокол.
- web/src/main.js — интерфейс, QR и чат.
- web/styles.css — собственный CSS без библиотек.
- scripts — локальная раздача и сборка из явного списка исходников.

Будущие рендер и симуляция должны быть отдельными модулями и взаимодействовать с сессией через сообщения. Надёжный упорядоченный канал предназначен для управляющих сообщений; частые снимки состояния потребуют отдельного ненадёжного канала и собственного протокола. Авторитетную симуляцию выполняет хост, гости передают ввод. Серверная игровая логика не нужна.

Раскладка адаптируется без медиазапросов: Grid auto-fit/minmax для секций, Flex с переносом для элементов управления, min()/clamp() для размеров. Все цвета CSS определены в :root; QR использует ту же палитру. Поля имеют шрифт 16px, интерактивные элементы — высоту не менее 44px.

qrcode@1.5.4 (MIT) загружается браузером с jsDelivr. Golos Text — с Google Fonts (SIL OFL). Сторонних исходников в Git и архиве нет. При недоступности CDN остаются текстовые ссылки и системный шрифт. QR генерируется локально, ссылки не передаются QR-сервису.

## Релизы

release.yml запускается по тегам v*, а также первоначальному 0.1.0. Выполняет тесты, собирает dist/, создаёт GitHub Release с ZIP и публикует тот же сайт в GitHub Pages. Источник Pages в настройках репозитория — GitHub Actions. Следующие версии: v0.1.1, v0.2.0 и далее.

В Settings → Environments → github-pages → Deployment branches and tags должны быть разрешены теги v* и первоначальный 0.1.0. Разрешения только для ветки main недостаточно для публикации из тегового workflow. Повторный запуск workflow обновляет архив существующего релиза.
